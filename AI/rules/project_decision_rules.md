# Project Decision Rules

## One Priority at a Time
- Focus on the current top task from `current_tasks.md`
- New ideas go to the backlog section, not the active list
- Finish and ship before starting something new

## Choose Changes That Matter
- Every change should improve portfolio quality or hiring outcomes
- Ask: "Would a recruiter notice this?" If no, it's low priority
- Ask: "Does this fix a real problem?" If no, it's polish — defer it

## Avoid Clever-but-Low-Value Work
- Don't refactor CSS "just because" — only if it fixes inconsistency
- Don't add features to show technical skill — the portfolio shows product thinking
- Don't optimize for edge cases that don't affect visitors
- Don't build infrastructure (CMS, CI/CD, testing) for a 9-page static site

## When to Add vs Remove vs Improve
- **Add** a project only if it strengthens hiring positioning (not just because it exists)
- **Remove** content that actively hurts credibility (thin case studies, unclear projects)
- **Improve** existing strong content before adding new content

## Decision Checklist
Before any change:
1. Does this align with the current top priority in `current_tasks.md`?
2. Does this improve hiring effectiveness?
3. Is this the smallest version of this change that works?
4. Does this preserve the portfolio's honest, direct tone?
5. Will this work on mobile?
